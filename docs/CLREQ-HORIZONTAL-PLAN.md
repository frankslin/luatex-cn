# 横排模式（CLReq 优先实现）设计与规划

> 配套文档：`docs/CLREQ-GAP-ANALYSIS.md`（差距分析）
> 本文回答：为什么先做横排、横排模式长什么样、怎么与竖排收敛、要花多少工。

---

## 1. 为什么「先横排」是对的

差距分析的初版曾把横排排在最后（P6，「不建议」），理由是与现有横排生态重复。
这个判断漏了三件事，本文修正后已回写差距分析（其 P0–P7 现按「竖排回流」口径描述）。

### 1.1 横排可以白嫖 TeX 的断行器

clreq 的换行禁则本质是「某些位置不许断、某些位置代价高」——这正是 TeX `penalty` 的语义；
可调间隙则正是 `glue` 的语义。横排模式下：

```
禁则       →  penalty（10000 / 可配置代价）
可调空间   →  glue（含 stretch / shrink）
不可分离   →  penalty 10000 包裹
```

**断行位置的搜索完全交给 TeX 的全局最优算法**，我们只负责在
`pre_linebreak_filter` 里把 glue/penalty 插对。而竖排引擎里这套东西全部要自己写
（现在 `layout-grid.lua` 的 kinsoku 是逐字符贪心的，做不到全局最优）。

同样一条 clreq 条款，横排的实现成本大约是竖排的 **1/3**。

### 1.2 真正该共享的东西，横排能先把它验证出来

我原来说「地基是弹性网格」，更准确的说法是：**地基是一个纯函数**——

> 给定：一行/一列的目标长度 L、一串带优先级的可调间隙 `{ideal, min, max, priority}`
> 求：每个间隙的最终值（按 clreq 的挤压 7 级 / 拉伸 2 级顺序依次用尽）

这个函数**与横排/竖排无关，与 TeX 无关**，是纯 Lua、纯数据、零依赖、极易单元测试的东西。
横排先用它（在 `post_linebreak_filter` 里对每一行做二次分配），竖排后用它
（在 `flush_buffer` 里对每一列做分配）。规则层（标点表、类别、优先级、禁则级别）同样共享。

所以「横排先行」不是绕路，而是**在成本最低的场地把共享内核跑通**。

### 1.3 生态里确实有空白

- `xeCJK` 的 `punctstyle` 只做标点压缩的粗粒度风格，没有 clreq 的优先级顺序、四级禁则、行尾悬挂。
- `luatexja` 完备但遵循的是日文 JLREQ，标点字面分布、引号体例、行间标点都按日文规范。
- 行间标点（专名号 / 书名号甲式 / 着重号）、汉语拼音行间注，在横排 LaTeX 生态里基本没有可用实现。

一个真正按 clreq 做的横排包，不是重复造轮子。

### 1.4 「无历史包袱」的额外价值

竖排引擎现在有 grid / natural 双轨、经验偏移量、无条件挤压等既有行为，
任何规范化改动都要担心古籍示例的基线变化（差距分析 R5）。横排是空地：
可以直接按 clreq 的模型建，建完之后**以它为准**去改造竖排，而不是反过来打补丁。

## 2. 形态：包优先，类其次

```
tex/
├── shared/                          # 新增：横竖排共享内核（纯 Lua，无 TeX 依赖）
│   ├── luatex-cn-punct-table.lua    # clreq 附录标点全表（单一数据源）
│   ├── luatex-cn-adjust.lua         # 一维优先级空间分配器（上文的"纯函数"）
│   └── luatex-cn-kinsoku.lua        # 禁则规则：四级 + 符号分离禁则
├── hori/                            # 新增：横排后端
│   ├── luatex-cn-hori.sty           # 主包（\usepackage 即可用）
│   ├── luatex-cn-hori-pipeline.lua  # pre/post_linebreak_filter 节点管道
│   ├── luatex-cn-hori-spacing.lua   # 中西间距、标点宽度调整
│   ├── luatex-cn-hori-linemark.lua  # 横排行间标点（单面装）
│   └── luatex-cn-hori-ruby.lua      # 拼音/注音行间注
└── ltc-cn-hbook.cls                 # 薄文档类：横排现代中文书籍
```

**为什么包优先**：`\usepackage{luatex-cn-hori}` 能被任何现有 LaTeX 文档采用，
获取用户与真实反馈的成本远低于「换一个文档类」。文档类只是把包 + 版心参数打包。

**与 luatexja / ctex 的关系**：`xeCJK` 只能运行在 XeTeX 上，与本包（LuaTeX）**根本不可能同时载入**，
不存在冲突问题。真正会打架的是 `luatexja`（同样在 LuaTeX 的断行回调里做标点压缩与禁则），
以及 `ctex`——它在 LuaLaTeX 下的后端就是 luatexja。策略是**检测并互斥**：
载入时若发现 `luatexja` 已加载，发出明确 error/warning 要求二选一；
文档里写清「本包与 luatexja/ctex（LuaLaTeX 模式）的 CJK 断行处理互斥」。不做兼容层——那是无底洞。

## 3. 节点管道设计

```
TeX 段落
   │
   ├─ pre_linebreak_filter ──────────────────────────────────┐
   │    1. 分类打标：查 punct-table，写 ATTR_PUNCT_CLASS      │
   │    2. 中西间距：CJK↔Latin 边界插入 glue                  │
   │         ideal 1/4 em, shrink→1/8 em, stretch→1/2 em      │
   │         例外（clreq）：行首/行尾不加；中文点号前后、      │
   │         开始夹注号之后、结束夹注号之前不加                │
   │    3. 标点宽度：按字面分布插 kern，可调部分插 glue        │
   │    4. 禁则：按级别插 penalty（行首禁 / 行尾禁）           │
   │    5. 不可分离：两字宽标点、数字串、数字+单位、货币       │
   │         用 penalty 10000 包裹                            │
   │    6. 每个 glue 上挂优先级属性（ATTR_ADJUST_PRIORITY）    │
   └──────────────────────────────────────────────────────────┘
   │
   ├─ TeX 断行（全局最优，免费）
   │
   ├─ post_linebreak_filter ─────────────────────────────────┐
   │    7. 逐行调用 shared/adjust.lua：按 clreq 优先级顺序     │
   │       重新分配余量（TeX 的比例分配 → clreq 的顺序分配）   │
   │    8. 行首/行尾标点挤压                                   │
   │    9. 行尾点号悬挂（横排默认关闭，可开）                  │
   │   10. 均排 / 单行对齐                                     │
   └──────────────────────────────────────────────────────────┘
   │
   └─ 行间标点 / 行间注：post_linebreak 后按行绘制
```

**第 7 步是关键**：TeX 断行后会按 glue 的 stretch/shrink **比例**同时伸缩全行，
而 clreq 要求**按优先级依次用尽**（先挤行末标点，再挤西文词距，再挤间隔号……）。
所以必须在 `post_linebreak_filter` 里把 TeX 的比例分配结果**覆盖掉**，改用共享分配器的结果。
这一步 `luatexja` 也是类似做法，路径成熟。

- ✅ `punct-table.lua`：clreq 附录全表数据化——字符 → {类别, 字面分布(大陆/港台), 宽度,
  可调空间(始/末/两侧), 不可分离, 直排右旋, 行首禁则, 行尾禁则}。
- ✅ `adjust.lua`：一维优先级空间分配器。输入 `{目标长度, 间隙列表}`，输出每个间隙的最终值。

### H3 · 横排行间标点（单面装）

- 专名号（下划线）、书名号甲式（波浪线）、着重号，均在文字**下方**。
- 「先线后点」原则：行间线紧贴汉字，着重号在其下。
- 相邻标注两侧缩短（≤ 1/8 em）；标点上不加着重号；疏排时着重号仍与字居中对齐。
- 行距下限校验：单面装 ≥ 0.5 em，不足时 warning。

**验收**：行间标点断言全绿。可复用竖排 `linemark.lua` 的波浪线贝塞尔实现。
**工作量：8–12 人日**

### H4 · 行间注（横排是主场）

- 汉语拼音标音：单字标音（注文在上、正文加大字距）与分词连写标音（词为基文、注文可在下）。
- 词对齐：注文短于基文 → 加大注文字距 / 居中；长于基文 → 加大基文字距。
- 相邻注文最小间距 ≥ 1/4 字宽；允许注文伸展到相邻基字上方。
- 中外文对照（注文在基文上方）。
- 注音符号横排（注音在汉字右侧，需预留 ≥ 1/2 字宽字距）——与竖排注音共享度量常量。

**验收**：注音度量断言全绿（3:10 比例、1:15 轻声等常量在共享层定义，横竖排同源）。
**工作量：15–25 人日**

### H5 · 段落与页面级

- 段首缩排（默认 2 字，多栏时可 1 字）、凸排（首行不缩、次行起固定量缩排）、段落缩排。
- 孤行孤字：段末孤字（前行借字 + 该行均排）、页首孤行；可配严格度。
  横排下 `\widowpenalty`/`\clubpenalty` 只是粗粒度，clreq 的「孤字」需自己判定。
- 标题：占行（整数倍行高）、单页起（右页起）、同行标题（一个全角空白间隔）、跨栏标题。
- 号数字号别名（初号…七号）。

**工作量：10–15 人日**

### H6 · 测试、文档与发布

- 横排回归套件（新增 `test/regression_test/hori/`）+ clreq 断言用例。
- `docs/CLREQ-CONFORMANCE.md` 填充横排列。
- 用户文档 / Wiki / 示例文档。

**工作量：10–14 人日**

## 7. 风险

| # | 风险 | 应对 |
|---|------|------|
| HR1 | `post_linebreak_filter` 里覆盖 TeX 的 glue 分配，可能与 `\hfill`、表格、数学环境冲突 | 只处理带 `ATTR_ADJUST_PRIORITY` 的 glue，其余原样保留；数学/表格内整体跳过 |
| HR2 | 与 luatexja / ctex（LuaLaTeX 后端即 luatexja）同时载入打架；xeCJK 为 XeTeX 专用，不构成冲突 | 载入期检测 luatexja + 明确 error/warning 要求二选一；文档写明互斥 |
| HR3 | 断行代价与禁则代价的调参 | penalty 值全部做成可配置键，提供三套预设，用真实文档做视觉评审 |
| HR4 | H4 拼音注音对字体与断行的影响（注文比基文宽会撑开字距） | 按 clreq「为正文设定较大字距」的做法，把字距预留做成显式参数而非自适应 |
| HR5 | 两条产品线并行导致规则实现发散 | **硬性约束：任何 clreq 规则只允许写在 `shared/`，后端只做编码与绘制** |
